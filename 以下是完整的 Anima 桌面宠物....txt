Anima 桌面宠物元框架开发规划书

> 项目名称: Anima

核心理念: 一切皆插件，可逆挂载，热插拔生态

灵感来源: Cordis 元框架、Koishi 机器人框架

目标: 构建一个最小内核 + 插件生态的桌面宠物平台，角色、皮肤、功能、AI 引擎均可自由组合

---

一、项目概述

1.1 产品定位

Anima 是一个元框架级别的桌面宠物平台。它本身不提供具体的角色、聊天或动画，而是提供：

- 物理法则：插件生命周期、事件总线、服务发现、副作用追踪
- 基础设施：配置中心、状态管理、热重载、UI 桥接
- 生态契约：标准化的插件接口，让第三方开发者可以开发角色卡、皮肤、AI 适配器、工具模组

类比：
- 房子 = Anima 内核
- 租客 = 角色卡插件（自带表情、动画、人设、触发逻辑）
- 家具 = 功能插件（聊天、天气、待办、音乐控制等）
- 装修 = 皮肤/UI 插件

1.2 核心设计原则

原则说明
最小内核框架本身 < 1000 行，不提供业务功能
一切皆插件配置、状态、动作、热重载、规则引擎、角色、聊天，全部是插件
可逆挂载插件卸载时，所有副作用（事件订阅、服务注册、定时器、UI 元素）自动 LIFO 回滚
依赖显式化插件通过 `dependencies` 声明依赖，启动时自动拓扑排序
服务发现插件不直接引用框架，通过 `Context.use("service_name")` 获取服务
热插拔文件系统监听 + 防抖重载，模组增删改无需重启应用
彻底重构不保留旧版兼容壳，所有业务逻辑以插件形式重新实现

2.2 核心层详细设计

2.2.1 App（最小内核）

```python
class App:
    def __init__(self):
        self.bus = EventBus()              # 事件总线
        self.registry = ServiceRegistry()  # 服务注册表
        self.config = {}                   # 全局配置引用
        self.lifecycle = LifecycleManager(self)

    async def start(self, plugins: List[Plugin]):
        await self.lifecycle.load_all(plugins)
        await self.lifecycle.enable_all()

    async def stop(self):
        await self.lifecycle.unload_all()
```

设计约束：App 本身不 import 任何业务模块。

2.2.2 EffectTracker（可逆性核心）

```python
class EffectTracker:
    def push(self, rollback: CleanupFn): ...
    def on(self, target, method, *args, **kwargs): ...
    async def rollback(self): ...  # LIFO 回滚
```

关键机制：
- 插件通过 `ctx.on()` 订阅事件 → 自动记录 `unsubscribe` 回滚
- 插件通过 `ctx.provide()` 注册服务 → 自动记录 `unregister` 回滚
- 插件通过 `ctx.task()` 创建任务 → 自动记录 `cancel` 回滚
- 插件通过 `ctx.on_cleanup()` 注册自定义回滚

2.2.3 LifecycleManager（生命周期 + 拓扑排序）

```python
class LifecycleManager:
    async def load_all(self, plugins: List[Plugin]):  # Kahn 拓扑排序
    async def enable(self, name: str):                # 调用 plugin.enable()
    async def disable(self, name: str):               # 调用 plugin.disable()
    async def unload(self, name: str):                # plugin.unload() + effects.rollback()
```

状态机：`unloaded → loaded → enabled → disabled → unloaded`

2.2.4 Context（插件的"房间钥匙"）

```python
class Context:
    app: App
    plugin: Plugin
    effects: EffectTracker
    config: dict  # 该插件的私有配置切片

    def on(self, event: str, handler: Callable): ...
    def emit(self, event: str, data: Any = None): ...
    def provide(self, service: Union[str, type], instance: Any): ...
    def use(self, service: Union[str, type], default=None): ...
    def task(self, coro: Coroutine) -> asyncio.Task: ...
    def on_cleanup(self, callback: Callable): ...
```

2.3 插件层设计

插件名职责依赖
`core.config`配置加载、持久化、分层读取无
`core.state`状态管理、变更广播、自动保存`core.config`
`core.actions`动作注册中心、内置动作(state_inc/state_set/emit)`core.state`
`core.bridge`UI 桥接、runtime 绑定、UI 动作注册(say/emote/anim)`core.actions`
`core.hotreload`文件系统监听、防抖重载、模组变更检测`core.loader`
`core.loader`模组扫描、分类、注册表构建`core.config`
`core.rule_engine`when/if 规则求值、动作触发、调试日志`core.actions`, `core.state`
`core.character_manager`角色卡生命周期、表情/动画管理、人设上下文`core.bridge`
`core.chat`LLM API 接入、聊天记录、导入导出、上下文管理`core.character_manager`, `core.actions`
`core.module_manager`功能插件的启用/禁用/配置、菜单管理所有 core 插件

2.4 数据流设计

```
用户点击/系统事件
    ↓
EventBus.emit("user.click")
    ↓
RuleEngine (订阅了 user.click)
    ↓ 求值 when/if 条件
ActionRegistry.execute("emote", {"name": "happy"})
    ↓
BridgePlugin._emote() → PetWindow.emote()
    ↓
UI 更新

同时:
StatePlugin.change("affinity", 10) → 广播 state.changed
    ↓
CharacterManager (订阅了 state.changed) → 切换表情阈值判断
```

六、API 设计规范

6.1 插件接口

```python
from anima.core import Plugin, Context

class MyPlugin(Plugin):
    name = "my.author.my_plugin"      # 全局唯一，反向域名风格
    version = "1.0.0"
    dependencies = ["core.config"]      # 依赖的其他插件 name

    async def load(self, ctx: Context):
        # 1. 读取配置
        api_key = ctx.config.get("api_key", "")

        # 2. 订阅事件
        ctx.on("user.click", self._on_click)

        # 3. 提供服务
        ctx.provide("my_service", self)

        # 4. 使用其他服务
        actions = ctx.use("actions")
        actions.register("my_action", self._my_action)

        # 5. 启动后台任务
        ctx.task(self._background_loop())

    async def enable(self):
        pass  # 开始业务逻辑

    async def disable(self):
        pass  # 暂停业务逻辑

    async def unload(self):
        pass  # 自定义清理（框架会自动回滚副作用）
```

6.2 事件命名规范

```
域.对象.动作

user.drag               # 用户拖拽角色
chat.message.sent       # 用户发送消息
chat.message.received   # 收到 AI 回复

plugin.disabled         # 插件禁用

```

# 类形式（类型安全）

七、风险与对策

风险影响对策
PyQt6 与 asyncio 冲突高使用 `qasync` 库统一事件循环，或确保所有 Qt 信号通过 `QTimer.singleShot` 桥接到 asyncio
插件循环依赖中LifecycleManager 拓扑排序时检测并抛出明确错误；开发阶段用静态分析工具检查
热重载状态丢失中关键状态由 StatePlugin 持久化；功能插件的 `_feature_data` 机制保留跨重载数据
第三方插件安全中Phase 5 引入签名验证；沙箱化执行（`RestrictedPython` 或子进程隔离）
GIL 阻塞 UI低LLM 请求用 `aiohttp` 异步；CPU 密集型任务用 `asyncio.to_thread` 或 `ProcessPoolExecutor`
旧数据迁移中Phase 2 提供数据迁移工具，自动将旧版 config.json / state.json 转换为新格式
